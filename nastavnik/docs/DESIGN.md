# Наставник — как устроено и почему

> Итог исследования и разработки: на чём основаны решения, что сознательно не делаем, как устроено приложение.

## 1. Принципы

1. **Подстраиваем то, где люди различаются и это можно измерить.** Остальное берём из исследований как есть.
2. **Судим по результату, а не по ощущению.** Цель — то, что вы помните через неделю, а не время в приложении. Даже YouTube перешёл от чистого времени просмотра к «ценному времени просмотра» по опросам.
3. **Числа считает код, Claude объясняет и генерирует.** LLM склонны соглашаться с пользователем, поэтому статистику ведёт приложение.
4. **Состояние живёт в базе, разговор с Claude — расходник.** Его можно сжать или начать заново, ничего не потеряв.
5. **Программа решает сама** (как в Aqua и «Сводке»). В настройки почти не нужно заходить. Проблема — баннер или карточка с кнопкой, которая её исправляет.

## 2. На чём основано

| Решение | Основание |
|---|---|
| Без «стилей обучения» вроде визуал/аудиал. Формат подачи проверяется результатом | Pashler et al., 2008: подтверждений гипотезы соответствия стилю нет. Willingham: форма подачи зависит от материала |
| Главная метрика — отложенный тест, а не оценка «понравилось» | Deslauriers et al., 2019: активное обучение дало больше знаний, но ощущалось менее полезным |
| Интервальные повторения, вспоминание без подсказки | Dunlosky et al., 2013: высшая оценка полезности у этих двух техник |
| Крючок-вопрос до объяснения | Эффект предварительной попытки (Kornell, Richland, 2009). Любопытство усиливает запоминание через дофаминовый контур (Gruber et al., 2014) |
| Задача до теории как вариант порядка | Sinha & Kapur, 2021: выигрыш в понимании и переносе. Проверяется на вас, а не принимается на веру |
| Схема по памяти как вариант закрепления | Blunt & Karpicke, 2014: схема по памяти работает как вспоминание |
| Сложность 80–90 % | Правило 85 % (Wilson et al., 2019) — как ориентир |
| Сначала знания уровня новичка, потом меньше подсказок | Эффект обратной экспертизы (Kalyuga) |
| Ядро — в начале, подарок-пик — в конце | Эффект конца исчезает за ~30 с (Glanzer & Cunitz, 1966). Конец решает, каким останется в памяти опыт: правило пика и конца, мета-анализ 2022 года, r = 0,58 |
| Открытая петля в конце сессии | Тяга вернуться к незаконченному подтверждена (эффект Овсянкиной, мета-анализ 2025). Лучшее запоминание незаконченного (эффект Зейгарник) — нет |
| Награды только информационные, без очков | Deci, Koestner & Ryan, 1999: ожидаемые материальные награды снижают интерес (d от −0,28 до −0,40), положительная обратная связь его повышает |
| Три метрики мотивации и правило тревоги | Дофамин отвечает за «хотеть», а не за «нравиться» (Berridge & Robinson). Тяга может расти без удовольствия |
| Главный триггер — после пропуска, серия с заморозкой | Buyalskaya et al., 2023: лучший предсказатель — время с прошлого раза. Megastudy Milkman et al., 2021: лучшая программа поощряла возвращение после пропуска. Silverman & Barasch, 2023: прерванная серия демотивирует меньше, если её можно «починить» |
| Напоминание только в дни без учёбы | Эффект напоминаний гаснет со временем (HeartSteps, Klasnja et al., 2019) |
| Точка усталости и время из ваших данных | Подстройка там, где у вас данных много: каждый ответ — наблюдение |
| Хронотип не используется | Rey-Mermet & Rothen, 2023 (N = 446): устойчивого эффекта синхронии нет |
| «Разговор» отделён от учёбы, без удержания | Чем больше ежедневное общение с ботом, тем больше одиночества и зависимости (MIT + OpenAI, 2025). Выплёскивание злости с прокручиванием усиливает злость (Bushman, 2002). Помогает назвать чувство (Lieberman, 2007) и взгляд со стороны (Kross) |

Сколько данных нужно, чтобы что-то узнать о себе (наше моделирование: 80 % мощности, наблюдение раз в день, автокорреляция 0,5):
- большой эффект — около 48 дней;
- средний — около 130;
- малый — около 360.

Если чередовать варианты неделями и сравнивать в лоб, ложных находок примерно в 4 раза больше нормы. Поэтому:
- форматы проверяются на учёбе, где каждая карточка — отдельное наблюдение;
- выбор делается случайно на каждую сессию;
- карточки одного понятия делят вес 1, чтобы понятия с большим числом карточек не перевешивали.

## 3. Архитектура

```
 таймер systemd --user (19:07, Persistent=true — догоняет после включения ПК)
   └─ nastavnik remind — уведомление с вопросом, на котором остановились (только если сегодня не занимались)

 Окно (PySide6): Главная · Учёба · Повторение · Прогресс · Разговор · Настройки
   │  сессия учёбы и разговор — во всё окно, текст Claude приходит потоком
   ▼
 Контроллер (app.py) ── фоновые потоки ── claude -p (подписка, stream-json)
   │                                         ├─ репетитор: --system-prompt-file tutor.md, --resume <тема>,
   │                                         │   инструменты только MCP «nastavnik»
   │                                         ├─ карта темы: new_topic.md, --json-schema
   │                                         └─ собеседник: listener.md, без инструментов; сводка — --json-schema
   ▼                                                    │
 SQLite (~/.local/share/nastavnik, WAL, бэкап) ◄── MCP-сервер (nastavnik mcp): get_state, add_concepts,
   темы · понятия · карточки (FSRS) · попытки ·        mark_concept, record_attempt, add_items, set_step, checkpoint
   сессии · сообщения · остановки · бандиты · события · память разговоров
```

**Ход учебной сессии.**
1. План (`learn/planner.py`): повторения по сроку, новое понятие, у которого начаты все предварительные, бюджет минут.
2. Форматы (`learn/bandit.py`).
3. Первая команда «начни сессию».
4. Claude ведёт шаблон и отмечает шаги через `set_step`, каждый ответ — через `record_attempt`. Время ответа и уверенность сервер берёт из сообщений, которые записало окно.
5. «Закончить»: карточки (`add_items`; первое повторение через ~3 дня, если практика прошла хорошо, иначе завтра), подарок, петля, `checkpoint`.
6. Оценка 1–5 → награда крючку и подарку.
7. Первое повторение карточки через 1,5+ дня после введения понятия — отложенный тест → награда порядку, подаче и закреплению той сессии.

**Контекст.**
- Разговор Claude привязан к теме. Его размер берётся из `usage` в потоке.
- После лимита начинается новый разговор, а первым ходом идёт «[состояние темы]».
- «No conversation found» обрабатывается так же — сам.
- Переменные окружения родительской сессии Claude Code (`CLAUDE_CODE_SESSION_ID` и др.) убираются, иначе все темы склеились бы в один разговор.

**Повторение заранее.**
- Можно повторить карточки до срока. FSRS учитывает такое повторение: при перерыве меньше суток действует формула кратковременной стабильности, срок сдвигается вперёд меньше, чем после планового повторения.
- Если с урока прошло меньше 1,5 дня, повторение пишется фазой `ahead`. Отложенный тест по этому понятию считается нечистым: вспомнить помогло повторение, а не формат. Поэтому оно не идёт в награду бандиту и не влияет на «пользу».
- Через 1,5+ дня даже повторение заранее — честный отложенный тест.
- Первый срок карточек из сессии считается по точности практики и закрепления, без крючка: крючок — вопрос до объяснения, ошибиться в нём нормально.

## 4. Доска

**Распознавание** (`sketch.py`, без Qt — его проверяют тесты):
- Штрих сначала сглаживается и упрощается.
- Замкнут ли контур: конец вернулся к началу, допускаются недолёт и перелёт.
- Какая фигура: по заполненности выпуклой оболочкой двух рамок:
  - рамка по осям: у ромба ~0,5;
  - наименьшая рамка под любым углом: у прямоугольника ~1 даже с наклоном, у овала ~0,79.
  На 900 случайных «рукописных» фигурах одна ошибка: круг принят за овал на границе пропорций.
- Открытый штрих привязывается к фигурам, у которых начался и закончился (допуск 18 px). Кусок внутри фигуры отрезается, концы хранятся как доли её ширины и высоты.
- Росчерк стрелки при движении узлов натягивается между концами поворотом и растяжением, а не выпрямляется.
- Наконечник одним росчерком отрезается по самой дальней от начала точке.

**Что уходит Claude:**
- Mermaid. Ключи узлов не меняются между отправками, поэтому можно показать, что изменилось.
- `%%`-комментарии для того, что структурой не выразить: свободные концы, надписи, рисунок от руки.
- Картинка PNG (светлая, до 1400 px) — только если есть подписи от руки. Она идёт тем же сообщением через `--input-format stream-json`.
- Проверено на настоящем Claude: подпись, нарисованную штрихами («Согласие»), он прочитал с картинки и спросил, куда ведёт свободная стрелка.

**Схемы Claude:**
- Mermaid разбирается (flowchart/graph, формы, подписи, пунктир, `&`, subgraph).
- Раскладка — по слоям, как у Sugiyama:
  - длиннейший путь;
  - промежуточные точки длинных стрелок на каждом слое — стрелки обходят узлы;
  - барицентры против пересечений;
  - выравнивание по соседям.
- Размер подписи меряет шрифт окна.

## 5. Надёжность: две находки

- **PRIMARY-выделение.** Qt начинает выделять текст мышью с первого пикселя сдвига. Щелчок с дрожанием руки выделял букву, и в Linux она уходила в PRIMARY: на X11 щелчок со сдвигом 2–3 px по тексту Claude давал «и», «р», «м». Программы, которые следят за выделением, считали, что вы что-то выделили. Теперь выделение мышью начинается после порога перетаскивания системы (`ui/textclick.py`). Проверено на X11 через XTEST и XFixes: щелчки ничего не объявляют, протяжка — как раньше.
- **Сборка мусора в фоновом потоке.** Claude работает в фоновых потоках, и автоматическая сборка мусора Python может сработать там. Qt-объект с таймером тогда удаляется не в своём потоке, и окно падает на следующем срабатывании таймера: segfault в `QTimerInfoList::activateTimers`, его поймал полный прогон тестов. Автоматическая сборка выключена, мусор собирается раз в 10 секунд в потоке окна (`app.main_thread_gc`).

```
nastavnik/
  README.md  install.sh  uninstall.sh  requirements*.txt
  prompts/        tutor · new_topic · listener · talk_summary
  nastavnik/
    __main__.py   nastavnik [gui | mcp | remind | status | export | install-timer | …]
    app.py        контроллер: окно, потоки, время, сессии, разговоры, вход в Claude, баннеры
    config.py     настройки (паттерн Aqua: типы, диапазоны, атомарная запись, .bak, .broken)
    storage.py    SQLite: схема, восстановление из бэкапа
    claude_cli.py обёртка над claude -p (из «Сводки») + сессии и размер контекста
    tutor.py      карта темы, сессия, ротация контекста
    talk.py       разговор, память, удаление переписки
    mcp_server.py инструменты репетитора
    sketch.py     доска: распознавание штрихов, привязки, Mermaid туда и обратно, раскладка схем
    systemd.py    напоминание
    learn/        fsrs · bandit · planner · metrics · engine
    ui/           theme · widgets (из Aqua) · look · chat · concept_map · board · textclick · pages ·
                  learn_view · review_view · talk_view · main_window · welcome · dialogs · tray
  tests/          test_learn (симуляции) · test_claude (поддельный claude + настоящий MCP) · test_gui (сценарии окна) ·
                  test_sketch (распознавание, Mermaid) · test_board (доска мышью, отправка Claude, повторение)
  docs/           DESIGN.md · screenshots/
```
